### 🐞 修复：重新抓取丢链接（两条独立根因）

1. **跨运行去重**：旧实现把全库已有作品 ID 装进去重器，采集时命中就跳过并继续往后捞更旧的 —— 导致拿到的不是最新、数量也可能凑不够。实测数据库中曾有 **40 条作品被标记「重复跳过」且从未入库**。现已收窄为「单个账号 + 单次采集内」去重，重试也重置。
2. **监听时机错误（竞态）**：作品列表接口的监听器注册晚于页面打开，第二次采集时（有缓存、响应更快）**首屏那批最新作品会在监听前返回并被丢弃**，只能捡到更旧的作品。这是「有时少、有时不对」的随机现象根源。现已将监听提前到页面导航之前。

> 现在的行为：每次抓取都从**最新一条**开始依次取满你指定的数量，不看发布日期、不管今天有没有采过。

### 🐞 其它修复

- **采集结果页启动残留**：打开程序时链接区强制为空，避免把上次采集的链接误当成本次结果
- **URL 悬停提示错位**：列索引改为按列名动态获取（插入新列后不再错位）
- **退出时残留定时器**：新增退出清理，消除窗口销毁后的无效回调
- **关闭程序未释放浏览器**：补上 Playwright 清理，避免驱动子进程残留
- 「反选」按钮实际行为是全部取消勾选，文案更正为「全不选」

### ⚡ 其它改进

- 采集性能：批量并发解析 + 去掉多余的登录探测页 + 固定等待改条件等待（单会话采集 23.9s → 20.2s）
