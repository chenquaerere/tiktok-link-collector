## 1. 项目总体目标

开发一个可交付个人使用的 **Windows 桌面软件**，批量采集**本人** TikTok 账号的作品链接：
导入账号 → 选择日期 → 选择账号 → 设置采集数量 → 严格串行采集 → 保存结果 → 复制/导出。

**关键边界**：这是「链接采集工具」，不是「视频下载工具」。只获取作品页面 URL，不下载视频。

**产品定位**：个人/小规模使用，实际账号规模约 **30～40 个**。不做企业级 SaaS，架构保留扩展性但 UI/交互复杂度围绕 30～40 账号设计。

### v1.1.0 关键事实（供后续维护）

- **聊天取链唯一可行路径**：`DivChatBox` 内卡片 → `__reactProps$*` 里的 `itemId` → `/api/im/item_detail/?itemId=` → 拼 `https://www.tiktok.com/@{author}/{video|photo}/{id}`。
  **不存在** `a[href*="/video/"]`；整页扫描会抓到会话列表/页头里的隐藏链接（曾导致「不管选哪个会话都拿到同一批错误链接」）。
- **顺序**：聊天窗口内垂直位置，最下面最新 → 按 `getBoundingClientRect().top` 降序取。
- **线程**：worker 线程禁止直接调 `after()` → 统一用 `BasePage.ui_call()` / 聊天页事件队列。
- **交互**：关键动作不用模态确认框（会因遮挡 + `grab_set` 造成「点了没反应」）。
- **布局**：任何空 `CTkFrame` 必须显式给 `width/height`（默认 200×200 会撑大父容器）。

## 7. UI/UX 改造计划（P31–P35）

> 详细审计见当轮《UI/UX 审计报告》。核心结论：**不是换色，而是产品化重构**。

1. **P31 Design System**：补全 Design Tokens（背景/文字/品牌/状态/边框 + 间距 4/8/12/16/20/24/32 + 圆角统一）；字体层级（App Title/Page Title/Section/Body/Secondary/Caption/Button/Table/Number）；抽出 Button/Card/PageHeader/StatCard/StatusBadge/Toast/Dialog/EmptyState/LoadingState/DataTable 到 `app/ui/components/`。
2. **P32 页面重构**：导航（图标+高亮）→ 仪表盘（当前任务实时区 + 修复重复统计卡片）→ 账号管理（搜索/筛选/全选列/分组/排序）→ 采集任务（执行态强反馈 + 账号间隔快捷设置）→ 采集结果（状态筛选 + URL 缩略/hover/点击复制）→ 历史/设置/日志。
3. **P33 交互系统**：全局 Toast 替代阻塞式 MessageBox；EmptyState/LoadingState/ErrorState；统一错误呈现（标题/账号/原因/建议 + 详情进日志）。
4. **P34 高DPI/响应式/性能**：`minsize` 调整至 900×600 可用；Windows DPI 缩放适配；导出/日志读文件走后台线程；账号列表大数据量优化。
5. **P35 最终验收**：新用户 10 秒走查 + 135 测试回归 + 真实三账号 smoke test + 重新打包便携版。

## 11. 最终验收标准

1. 新用户打开程序 10 秒内理解用途并找到「账号管理 → 采集任务 → 采集结果」。
2. 首次采集流程清晰：导入账号 → 选日期 → 选账号 → 设数量 → 开始。
3. 采集中能清楚看到：当前账号、进度、实时状态、成功/失败数。
4. 结果可快速查看/筛选/复制/导出，复制有 Toast 反馈。
5. 聊天采集能真正进入所选对话框，取到该会话内分享的真实链接（最新 → 最旧）。
6. 189 测试全过 + 真实端到端 smoke test 通过（群聊 + 好友）。
7. 900×600 窗口可用，100–200% DPI 缩放不变形。
8. 无阻塞式弹窗打扰、无默认控件拼接感、无卡顿、无「点了没反应」。
