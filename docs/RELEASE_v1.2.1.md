## v1.2.1 — 修复「置顶作品挤掉新作品」+ 近期置顶额外采集

本次为**缺陷修复版**：定位并修掉「重新抓取少链接」的**第三个根因** —— 账号**置顶作品**。

### 🐞 修复：置顶作品挤掉新作品

- **现象**：部分账号采集「最新 N 条」时**少拿链接**。用户在回填时发现——有的账号明明发布了新作品，却没被采到。
- **根因**：TikTok 主页**最多可置顶 3 条作品**，置顶作品会被排在列表**最前面**（而不是按发布时间）。
  程序按列表顺序取「最新 N 条」时，置顶的（较旧）作品先被取走占了名额 → 真正新发布的作品被挤掉。
  用户实测：2 个账号各置顶 1 条 → 各少拿 1 条新作品。
- **实测证据**：扫描 21 个账号后定位到置顶账号，其列表顺序为
  `1. 09-14 发布（置顶）→ 2. 09-27 发布（真正最新）→ …`，头部出现时间倒挂。
- **数据结构确认**：作品列表接口的每条记录带 `isPinnedItem` 字段 —— **置顶条目 `true`，普通条目 `null`**。
  （注意：该字段只在有置顶的账号上才出现，无置顶账号看不到。）

### ✨ 新增规则：近期置顶额外采集

置顶作品不一定都要丢弃 —— 如果它本身就是**新作品**，也应该拿下来：

| 置顶作品的发布时间 | 处理方式 | 你填 3 条时的结果 |
| --- | --- | --- |
| **今天 / 昨天** | **额外采集**（不占数量名额） | **4 条**（3 条最新 + 1 条置顶） |
| 前天及更早 | 跳过、不占名额 | 3 条（置顶被跳过） |

- 「今天/昨天」按程序配置的时区判断
- **数量名额只由「非置顶作品」占用**，置顶额外累加，不影响「采满即停」的判定
- 任务状态也按非置顶数判定，避免「只采到置顶、非置顶没采到」被误判为完成
- 采集结束的提示会分别显示「**额外采集 N 条置顶（今天/昨天发布，不占数量）**」与「**跳过 N 条旧置顶作品（不计入数量）**」
